# Partner Repository Access

This repository is private. Every partner must be granted access before they can clone, download, or view the lab.

## Add a collaborator

1. Open the repository on GitHub.
2. Select **Settings**.
3. Select **Collaborators and teams**.
4. Select **Add people**.
5. Enter the partner's GitHub username or verified email address.
6. Grant the minimum repository role required for the workshop.
7. Ask the partner to accept the invitation before the session.

## Recommended access model

| Audience | Recommended role |
|---|---|
| Lab participant | Read |
| Proctor or content reviewer | Triage or Write |
| Lab maintainer | Maintain |
| Repository owner | Admin |

Use **Read** access for participants unless they need to contribute changes directly.

## Pre-session verification

- [ ] Every participant has a GitHub account.
- [ ] Every participant has received an invitation.
- [ ] Every participant has accepted the invitation.
- [ ] Participants can open the repository while signed in.
- [ ] Participants can clone or download the repository.
- [ ] Access expiration or removal has an assigned owner and date.

## Bulk or recurring delivery

For recurring partner workshops, use a GitHub organization team rather than managing individuals repeatedly:

1. Create a team for the workshop audience.
2. Grant the team Read access to the repository.
3. Add and remove partners through team membership.
4. Review team membership after each workshop.

## Remove access

After the engagement:

1. Review the collaborator or team list.
2. Remove access that is no longer required.
3. Confirm that no workshop-specific credentials or secrets were committed.
4. Retain only the access required for continued collaboration.

Partner invitations are intentionally not automated by this repository. A repository administrator must review and approve each collaborator or team.
